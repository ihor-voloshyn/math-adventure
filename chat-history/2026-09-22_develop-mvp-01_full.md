Я в предыдущем ответе описал **текущее фактическое состояние**, но не то, **как мы договорились, что система должна работать**.

Наша схема должна быть **двухслойной**:

### 1. Полный исходный текст чата — архив

Между двумя командами:

**«сохрани чат» → весь последующий чат → «сохрани чат»**

мы должны сохранять **полный исходный текст переписки**, а не summary.

Например:

```
chat-history/
  2026-09-22_develop-mvp-01/
    chat-001.md
    chat-002.md
    ...
```

или один файл на сегмент:

```
chat-history/2026-09-22_develop-mvp-01_full.md
```

Это будет **источник истины для восстановления идей и контекста**.

Из него потом можно:
- восстановить, почему мы приняли решение;
- найти потерянную идею;
- проверить, что именно ты говорил;
- сверить реализацию с первоначальным обсуждением;
- понять, почему нынешнее решение отличается от старого.

### 2. Checkpoint / Summary — быстрый индекс

Одновременно `сохрани чат` создаёт:

```
chat/checkpoints/...
chat/CURRENT_STATE.md
decisions/DECISIONS.md
```

Они нужны **мне прежде всего для быстрого продолжения**.

То есть при:

**«продолжай»**

я сначала читаю:

```
CURRENT_STATE
    ↓
последний checkpoint
    ↓
DECISIONS
    ↓
актуальные canonical docs
    ↓
код / PR
```

и **не обязан каждый раз перечитывать весь архив чата**.

Если возникает спор, потерянная деталь или нужно проверить происхождение решения:

```
Summary
   ↓
Full chat archive
   ↓
проверка идеи/контекста
```
