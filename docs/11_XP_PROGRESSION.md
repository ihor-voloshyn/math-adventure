# 11_XP_PROGRESSION.md

**Проект:** Math Adventure  
**Документ:** XP & RPG Level Progression  
**Версия:** 1.0  
**Статус:** APPROVED  
**Дата:** 2026-09-22

## 1. Назначение

XP — самостоятельная система игрового прогресса. Её задача — поддерживать ощущение приключения и долгосрочной цели, не превращая математические задания в бесконечный источник фарма.

> **Mastery rewards learning. XP rewards adventure.**

## 2. Независимые системы

- **Mastery** — математическое обучение и доступ к математически зависимому контенту.
- **XP** — игровой опыт и RPG Level.
- **Coins** — игровая валюта.
- **Loot** — предметные награды.

Системы могут изменяться одним игровым событием, но не заменяют друг друга.

## 3. XP не начисляется за каждый математический ответ

MVP не использует прямое правило «правильный ответ → XP». Математический ответ влияет на математическое действие и Mastery. Затем успешное игровое событие может дать XP.

Это предотвращает стратегию «решать самые лёгкие задачи много раз ради прокачки героя».

## 4. Основные источники XP

1. завершение квеста;
2. победа в бою;
3. первое открытие значимого места;
4. завершение игровой головоломки;
5. сюжетное событие;
6. milestone развития дома/территории;
7. особое открытие или достижение.

## 5. Повторное прохождение и anti-farming

- первое завершение значимого контента → полный XP;
- повтор без улучшения сохранённого результата → 0 XP;
- повтор с улучшением сохранённого результата → ограниченный небольшой XP-бонус;
- уникальные открытия и достижения дают XP преимущественно один раз.

Лёгкий повторяемый контент не должен становиться оптимальным способом прокачки.

## 6. XP и математическая Difficulty

Нельзя использовать правило «более высокая математическая Difficulty автоматически даёт больше XP», если это заставляет Adaptive Engine выбирать неподходящую ребёнку задачу.

**Adaptive Engine → подходящая математическая Difficulty.**  
**Game/Economy → игровая награда.**

## 7. XP и Mastery

RPG Level и Mastery независимы. Например, RPG Level 12 и ADD_CROSS_TEN Mastery 2 могут существовать одновременно. RPG Level никогда не обходит mathematical prerequisites.

## 8. XP Thresholds

MVP использует cumulative-кривую:

**XPRequired(L) = 50 × (L − 1)²** для Level 1–30.

| Level | Cumulative XP |
|---:|---:|
| 1 | 0 |
| 2 | 50 |
| 3 | 200 |
| 4 | 450 |
| 5 | 800 |
| 10 | 4,050 |
| 15 | 9,800 |
| 20 | 18,050 |
| 25 | 28,800 |
| 30 | 42,050 |

Это cumulative XP, а не стоимость отдельного уровня.

## 9. Почему кривая ускоряется

Первые уровни должны быстро показать ребёнку ощущение роста и открыть первые игровые изменения. Поздние уровни требуют большего приключения и не должны достигаться за счёт гринда лёгких математических задач.

## 10. Level Up

При достижении порога: **XP → Level Up → Reward/Unlock → заметная визуальная обратная связь.**

Level Up должен быть событием: анимация, изменение героя/мира и понятное сообщение о новом открытии.

## 11. Milestones

Уровни 5, 10, 15, 20, 25 и 30 используют крупные milestones и соответствуют `10_RPG_PROGRESSION.md`.

## 12. Скорость, ошибки и подсказки

- fast ≠ more XP;
- slow ≠ less XP;
- неправильный математический ответ не отнимает XP;
- математическая подсказка не уменьшает XP.

Ошибки влияют на математическую адаптацию и Mastery evidence, но не превращаются в XP-наказание.

## 13. Поражение

Поражение не отнимает уже подтверждённый XP. Незавершённые награды текущего игрового захода могут не сохраняться согласно persistence rules.

## 14. XP Event

Концептуальная модель: `eventId`, `playerId`, `eventType`, `sourceId`, `xpAmount`, `timestamp`.

Каждое событие имеет уникальный `eventId`.

## 15. Idempotency

Один и тот же `eventId` не может начислить XP дважды. Это защищает от повторной обработки после crash, retry или sync.

## 16. Offline-first

XP начисляется локально.

**Local Event → Sync → Server Validation → Authoritative Progression.**

Клиент не является окончательным источником истины для защищённого прогресса.

## 17. Ownership

**Game Engine / Game Progression:** игровые события, XP eligibility, RPG Level, level-up и game unlocks.

**Reward/Economy:** Coins, Loot и экономические последствия.

**Math Engine / Mastery:** математическая правильность, Mastery и математическая доступность.

**Adaptive Engine:** следующий математический шаг, Skill, Difficulty, Mode и Context.

Adaptive Engine не оптимизирует XP.

## 18. UX

После математической задачи ребёнок должен ощущать не «я сделал тест», а «я помог герою пройти дальше».

Математика должна быть встроена в игровое действие, а не просто визуально оформлена как тест. Исследования образовательных математических игр поддерживают важность адаптивности, обратной связи и интеграции учебного содержания с игровым контекстом; сама геймификация без такого баланса не гарантирует улучшения обучения.

## 19. Acceptance Criteria

1. XP не зависит напрямую от каждого математического ответа.
2. Лёгкий повторяемый контент не позволяет бесконечно фармить XP.
3. Первый значимый игровой успех даёт понятный прогресс.
4. Level Up заметен ребёнку.
5. Математическая ошибка не уменьшает XP.
6. Математическая подсказка не уменьшает XP.
7. RPG Level не обходит Mastery.
8. Один `eventId` не начисляет XP дважды.
9. XP работает offline.
10. Level 30 достигается в нормальном прохождении MVP без обязательного гринда.
