# 1. Назначение

Документ фиксирует MVP-модель RPG-прогрессии персонажа.

RPG Level является самостоятельной игровой системой и не заменяет математическое Mastery.

---

# 2. Независимые системы прогресса

В MVP существуют три независимые системы:

| Система | Назначение |
|---|---|
| XP | накопление игрового опыта |
| RPG Level | уровень игрового/персонажного прогресса |
| Coins | игровая валюта |
| Mastery | математическое освоение навыков |

Связи:

```
Игровые действия → XP → RPG Level
Математические результаты → Mastery
Игровые награды → Coins
```

RPG Level не может заменить или обойти Mastery как образовательный ограничитель.

Mastery не конвертируется автоматически в RPG Level.

---

# 3. Основной принцип RPG Level

RPG Level отвечает на вопрос:

> «Насколько далеко я продвинулся в приключении?»

Mastery отвечает на вопрос:

> «Насколько хорошо я освоил математику?»

RPG Level должен развивать ощущение приключения, а не служить скрытым математическим уровнем.

---

# 4. Диапазон MVP

MVP использует:

**RPG Level 1–30.**

Конкретная XP-формула и пороги перехода между уровнями в этом документе не фиксируются.

Они будут определены отдельным решением после балансировки игровых наград и длительности прогрессии.

---

# 5. Типы наград за уровень

Повышение RPG Level может открывать:

- способности героя;
- экипировку;
- косметические элементы;
- новые игровые возможности;
- новые участки мира;
- новые квесты;
- развитие дома;
- развитие территории;
- развитие питомца;
- сюжетные milestones.

Не каждый уровень обязан давать боевой бонус.

---

# 6. Milestone Levels

Каждый пятый уровень является крупным milestone:

- Level 5 — первый большой milestone;
- Level 10 — крупное расширение исследования;
- Level 15 — новый этап приключения;
- Level 20 — подземелье / крупный сюжетный этап;
- Level 25 — крупное расширение мира;
- Level 30 — финальный milestone первой большой сюжетной арки MVP.

---

# 7. Уровни 1–5 — Начало приключения

## Level 1 — Начало приключения

Стартовый уровень.

Доступны:

- базовый дом;
- стартовая экипировка;
- первый питомец;
- деревня;
- базовые игровые механики.

## Level 2 — Первые шаги

Возможные награды:

- первый небольшой апгрейд дома;
- дополнительная косметика;
- первое развитие питомца.

## Level 3 — Искатель приключений

Возможные награды:

- новая экипировка;
- дополнительная зона деревни;
- новые небольшие задания.

## Level 4 — Герой деревни

Возможные награды:

- улучшение дома;
- новый элемент экипировки;
- новые NPC/взаимодействия.

## Level 5 — Ученик героя

Первый крупный milestone.

Открывает:

- первую полноценную способность;
- заметное улучшение дома;
- новый элемент игрового пространства;
- особую косметическую награду.

# 13. Визуальная прогрессия

Каждые пять уровней должны давать заметный визуальный сигнал роста героя:

```
Level 1  → Новичок
Level 5  → Ученик героя
Level 10 → Исследователь
Level 15 → Герой
Level 20 → Защитник
Level 25 → Чемпион
Level 30 → Хранитель
```

Визуальная прогрессия может включать:

- броню;
- одежду;
- аксессуары;
- внешний вид питомца;
- дом;
- территорию;
- косметические эффекты.

Конкретный художественный дизайн определяется World/Art/UX документами.

---

# 14. Боевые характеристики

RPG Level не должен давать настолько сильный прирост боевой мощности, чтобы высокий уровень компенсировал отсутствие математического понимания.

Поэтому MVP не использует простой принцип:

```
Level ↑ → огромный рост HP/Attack
```

Вместо этого основная ценность RPG Level — новые возможности, контент, способности, экипировка и развитие мира.

Точные боевые характеристики определяются отдельным Game Design решением.

---

# 15. Связь с Mastery

RPG Level и Mastery работают параллельно:

```
                    GAME PROGRESS
                         │
                         ▼
                    XP → RPG Level
                         │
                         ├── Hero
                         ├── World
                         ├── Home
                         └── Pet

                    MATH PROGRESS
                         │
                         ▼
                       Mastery
                         │
                         └── Mathematical access
```

Пример:

Ребёнок может иметь высокий RPG Level и одновременно недостаточный Mastery по конкретному математическому навыку.

В этом случае:

- игровой персонаж продолжает быть развитым;
- соответствующий математически зависимый контент остаётся недоступным;
- Adaptive Engine продолжает работать на основании Mastery.

---

# 16. Ограничения

Не допускается:

1. использовать RPG Level как замену Mastery;
2. открывать математические навыки только на основании RPG Level;
3. автоматически повышать Mastery за RPG Level;
4. автоматически повышать RPG Level только за правильный математический ответ;
5. делать скорость получения XP главным критерием математического прогресса;
6. продавать RPG Level или математический прогресс за реальные деньги;
7. делать высокий RPG Level достаточным для обхода математических prerequisites.

---

# 17. XP Formula — отдельное решение

Этот документ намеренно не определяет:

- XP за бой;
- XP за квест;
- XP за исследование;
- XP за головоломку;
- XP за открытие мира;
- XP за другие действия;
- пороги XP для Level 1–30;
- максимальный XP;
- возможность повторного получения XP;
- анти-farming правила.

Эти параметры должны быть сбалансированы отдельно.

---

# 18. Экономическая граница

RPG Level и Coins независимы.

Одно игровое событие может потенциально дать одновременно:

```
XP + Coins + другие игровые награды
```

но это не означает, что XP и Coins имеют одинаковые правила начисления.

Reward/Economy система определяет игровые последствия.

---

# 19. Будущая расширяемость

Архитектура должна позволять в будущем добавить:

- уровни выше 30;
- новые milestone;
- специализации;
- классовые способности;
- расширенное развитие питомца;
- развитие замка;
- новые регионы;
- prestige/endgame;
- дополнительные сюжетные арки.

Эти системы не являются частью MVP.

---

# 20. Статус

**RPG Progression 1.0 — APPROVED**

Это решение фиксирует структуру RPG Level 1–30.

Следующими отдельными решениями должны стать:

1. источники XP;
2. XP thresholds;
3. награды/способности;
4. боевые характеристики;
5. детальная связь RPG Level с Game Engine.

Ни одно из этих решений не должно изменять образовательную роль Mastery без отдельного Product Owner решения.
